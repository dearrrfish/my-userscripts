# Local rule and skill evolution

Evolution requires a complete run with passed parse, metadata, pinned lint, exact-output fixtures and real FireMonkey browser acceptance. The backend rechecks source/candidate history, profile, active rules, skill, tool and dependency bytes, frozen suites and observations. An unverified input such as the current GreasyFork 454120 candidate cannot create a proposal.

`@fm/evolution` exports `propose({workspaceRoot,auditDir,origin,draft,replays})`, `approvalTemplate(proposal,approver,time)` `apply({workspaceRoot,proposalDir,approval,auditDir})` and `reject({workspaceRoot,proposalDir,auditDir,reason?})`. It imports the converter and contracts, never the CLI. The host loads `RunEvidenceContext`; the backend independently checks it. `auditDir` must be inside project `.fm/`.

A draft contains `reason`, `scope: "rules" | "skill" | "both"`, explicit text `files: [{path,content}]`, `regressionFixtures`, and `regressions: [{id,kind,source,expectedOutputHash,expectedStatus}]`. Positive fixtures must exercise a changed rule; negative fixtures must not match it; idempotence fixtures must produce the same bytes twice. At least one fixture file must contain the exact regression array serialized with `JSON.stringify(array,null,2) + "\n"`. At least one separately saved complete replay with a distinct run ID is required in addition to the originating run; duplicate replay IDs are rejected. Original source/candidate snapshots are retained.

Allowed proposal paths are JSON rules in `rules/`, owned JSON fixtures in `fixtures/evolution/`, and Markdown summaries in `docs/evolution/`. Canonical relative paths, no aliases/symlinks, text only, no deletions, stable existing rule IDs with increasing revisions, and exact verified target ranges are required. Executable transform changes are rejected. Skill scope must change SKILL.md or Markdown under `skills/fm-convert/references/`; both scope must change those resources and rules. No scripts, agent UI metadata, deletions, or executable transforms can be proposed. Positive/negative rule-match assertions apply when rules change; converter regressions and idempotence apply to every scope. PR approval awaits the deferred CI workflow and remains rejected. Active evolution requires the canonical source workspace to equal the runtime root; installed portable bundles cannot modify active project resources.

Proposal files are saved under ignored `.fm/evolution/<proposal-id>/`: immutable `proposal.json`, `patch.json`, `report.md`, and `evidence.json`. The report displays reason, risk, verification digest and all changed bytes with a complete diff. Proposal hash excludes only its own hash and mutable status, while binding patch/report/base/verification hashes. Apply revalidates all those bindings and replays the overlay against successful original sources. Any output or blocked/manual/API/context obligation change requires new real browser evidence. Same-output reuse does not establish new browser behavior.

The human must review the entire report and deliberately approve its exact hashes. `approvalTemplate` only constructs a contract-valid record; it does not attest that a human reviewed anything, and the host must not call it as automatic approval. Local JSON records are an explicit human trust boundary, not cryptographic identity proof. A changed proposal invalidates old approval.

Apply takes an exclusive lock, persists audit before mutations, checks current bases, installs new files exclusively by hard link and updates existing files by rename, and restores earlier writes if a later write or audit fails. The lock coordinates cooperating evolution writers; filesystem readers can observe intermediate files, and concurrent unrelated writers must not edit proposal-owned paths. Unrelated files are preserved. Success is recorded separately in `applied.json`, keeping original proposal/evidence history immutable; applied/rejected decisions are written completely to private temporary files and installed exclusively by atomic hard link, and every existing decision must match its full structure and proposal/approval hashes; repeat application is rejected. Rejection writes a separate immutable `rejected.json` decision and prevents application without changing the original proposal. A successful new-file link is immediately registered for rollback before temporary cleanup. Partial decision writes install no marker, so rollback/rejection failures can be retried. If temporary cleanup fails after a complete decision has committed, the valid decision remains authoritative and an ignored private temporary file may remain. Failed transactions retain sanitized audit records. Raw proposals, evidence and audit logs stay in ignored `.fm/`; approved summaries under `docs/evolution/` can be versioned.

The regression tests use synthetic observations in ignored workspaces. They do not attest a real FireMonkey session. No actual repository rule evolution is performed by those tests.

For skill or both drafts, `behaviorTemplate({workspaceRoot,auditDir,origin,draft,replays})` first checks complete stored run evidence and converter regressions, then loads the fixed host `scripts/portable-runner.mjs`. Proposed code is never imported. The runner builds a retained isolated candidate bundle from proposed text and checks four offline CLI invariants. The fifth case, and the instruction-following assessment across all cases, require a deliberate independent evaluator. A pending template contains placeholder observations and never supplies passed evidence.

The draft must supply `skillBehavior` and `behaviorArtifacts: [{path,content}]`. All five frozen mandatory cases must pass, with a deliberate evaluator and nonfuture timestamp. Full observation digest binds candidate resource hash, frozen suite, trusted runner/builder/case bytes, machine result, complete originating/replay evidence, actor, time, and each artifact reference. `forward-report.md` is required. Artifact paths are canonical logical relative names; they are stored as immutable bytes in proposal evidence and are never interpreted as output destinations. Every supplied artifact must be referenced by a case or report hash, and every reference must match supplied bytes. Duplicate or unbound artifacts are rejected. The full local report includes every observation and artifact in addition to complete changed-file diffs.

Propose and apply independently rerun the fixed host machine checks and compare the same bindings. All active SKILL resources (SKILL.md, references, agents, scripts, assets) contribute to the skill hash, so a successful skill edit invalidates old run receipts. Host support file additions, removals and byte changes likewise invalidate stored evidence. Human JSON receipts remain deliberate trust records, not authenticated identity proof. The synthetic library tests use a clearly labelled independently installed host stub for protocol coverage; actual portable runner execution and independent forward evaluation are separate integration checks.

The backend independently validates every originating and replay run's persisted manifest: canonical ignored run/root, schema, script identity, profile, configuration and lineage, and materialized/non-dry status. It rechecks the current materialized output and recorded local input bytes, any bound source-lock bytes and configured snapshot origin/hash/dependencies, plus the applicable current configured local upstream even when the recorded input is a separate unchanged snapshot. Missing files, symlinks and path aliases fail closed. The complete persisted manifest contributes to proposal verification, so removing a provenance field after proposal cannot bypass replay freshness. Rule paths use ordinal ordering consistently with CLI conversion and release hashing, including mixed-case and punctuation filenames.
