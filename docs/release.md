# Local release preparation and finalization

The release backend creates local artifacts only. It performs no network publication, Git commit, Git version bump, or upstream code execution. Publication defaults to `disabled`.

A configured `local` policy must supply an actual HTTP(S) base URL, license evidence, a numeric `versionMajor`, and `initialRevision`. Preparation requires an original complete conversion: parsing, metadata, pinned lint, exact-output fixture observations, and deliberate browser acceptance must all pass. The backend reruns static verification and validates source/candidate snapshots, profile/rules bytes, dependency content, configured identity/checklist, and all receipt bindings. Pending browser evidence cannot prepare a release.

License evidence must be readable and match its declared SHA256. A workspace-relative evidence reference reads that local file. An HTTP(S) evidence reference requires previously captured bytes in `.fm/dependencies/<hash>`; the release backend does not download them. This establishes the supplied evidence bytes, rather than giving a legal interpretation of those bytes.

`prepareCandidate({context, script, releaseRoot, auditDir})` returns frozen source text, output/version/policy hashes, reservation ID, upstream input hash, original run ID, and local state paths. The adapter creates a **new derived run** that keeps the original source/input hash, uses the frozen candidate, records the original run as parent, and starts new fixture/browser evidence. `finalizeRelease` accepts only the newly complete derived run with the exact frozen bytes, reservation and policy. Browser acceptance of the original conversion does not attest the release metadata.

Preparation replaces only canonical `version`, `downloadURL`, and `updateURL` entries. It preserves identity, attribution, unknown/localized/repeated metadata and program bytes. Final output is the script ID plus `.user.js`, `.meta.js`, and `.manifest.json` under the explicit release directory. Download/update URLs use the configured base URL and stable script ID filenames. Release directories cannot overlap `.fm` state/run storage or traverse symlinks.

Reservations persist at `.fm/releases/<scriptId>/state.json` plus immutable reservation records. An identical upstream input, pre-release output, profile, rule set, identity and publish policy reuses the same reservation/version/bytes, including unfinished reservations. Different inputs reserve the next revision. The release root participates in policy binding. A busy lock fails closed; investigate stale locks manually. Audit records must persist before reservation or artifact writes. Immutable complete reservation records act as a journal: if updating the state index fails, the next locked operation rebuilds that index from validated records and reuses the reserved version. A partially written temporary record is never installed at its final path.

Versions use `major.revision`, with components bounded to Mozilla's signed 32-bit range. The supported upstream version subset is nonnegative dot-separated canonical decimal components; missing parts compare equal to zero. Comparison follows the numeric behavior of Mozilla's [VersionComparator implementation](https://raw.githubusercontent.com/mozilla/gecko-dev/master/xpcom/base/nsVersionComparator.cpp), rather than lexical or SemVer ordering: `99.10 > 99.9` and `98 == 98.0`. Leading zeros, prerelease strings, plus signs, wildcards and overflow are rejected because this backend does not implement the complete Mozilla grammar. The configured starting version must exceed upstream; a configured major below previously reserved versions is blocked, and revision exhaustion is blocked.

Finalization checks ownership hashes before replacing existing files. Unrelated or modified outputs cause a collision error. It installs complete temporary bytes while holding the script reservation lock and rolls back installed files if an ordinary filesystem operation fails. Repeat finalization of the same exact version is permitted. A process crash during multi-file installation is not an atomic filesystem transaction: audit/ownership mismatches fail closed on retry and require inspection. The lock is local to this workspace and does not coordinate independent workspace copies.

Run `node scripts/test-release.mjs` after building the CLI. Its synthetic workspaces stay ignored under `.fm`; synthetic receipts are explicitly labelled and do not establish FireMonkey compatibility for the development target.

The direct backend also reconciles the saved `.fm/runs/<runId>/manifest.json`, complete result, frozen browser/fixture suites, saved `acceptance.json`/`fixture.json`, release lineage and bound configuration before reserving or publishing. Supplied context alone cannot replace those records. It enumerates the current `.js` runtime modules in CLI/contracts/converter/evolution plus the four required entry/lock files and compares the exact pin keyset and bytes; omitted pins and added, removed or changed modules block release. The configured script must equal the selected script from the hash-bound configuration. Current materialized input/output/source-lock bytes and configured local upstream bytes are checked when present.
