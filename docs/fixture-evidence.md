# Fixture observation evidence

`fm fixtures template --run RUN` creates a pending observation bound to the captured source, candidate bytes, dependencies, target profile, rules, SKILL, tool version and frozen fixture suite. Fill in the verifier, observation timestamp, executed command or manual procedure, status and concrete evidence for every case. Recalculate `evidenceDigest` with `fixtureObservationDigest` from `@fm/contracts` (also re-exported by `packages/cli/dist/verification/fixtures.js`), then submit using `fm fixtures record --run RUN --file PATH`. Raw observations and immutable history belong under ignored `.fm/` storage.

Standalone suite `standalone-regression-v1` requires metadata retention, API/context behavior and idempotence. `greasyfork-454120-regression-v1` requires metadata retention, storage compatibility, document-start initialization, unsafeWindow bindings and idempotence. Every case is mandatory. Suite hashes cover the suite ID and ordered case IDs/mandatory flags. Observation digests cover the complete observation with recursively sorted object keys using ordinal ordering and preserved array order, excluding only `evidenceDigest`.

Compare retained metadata against the captured source; examine each granted API in the actual injection context; reconvert the candidate with identical inputs to assess idempotence. For GreasyFork 454120, record storage values before and after reload, early initialization behavior, and unsafeWindow access in the intended frames. A case needs the actual procedure and observed result, including any failure. Placeholder actors, future timestamps, changed bindings, altered or duplicate cases and empty passed observations are rejected. Mandatory `not-applicable` cases remain pending. Any mandatory failure makes fixture verification failed.

Command strings are descriptions and are never executed by this backend. Human observations are a deliberate trust boundary, not authenticated proof. Generic unit tests and static parsing do not establish target-specific fixture success. Synthetic test observations exercise validators only and do not establish GreasyFork 454120 compatibility. Browser acceptance remains a separate required receipt; fixture recording alone cannot complete conversion.

`mergeFixtureVerification` preserves other verification records and replaces only the fixture record after validating the observation against fresh run context. The host must load fresh profile bytes, rule bytes and artifact bytes, check captured dependencies/tool/SKILL freshness and preserve immutable receipt history.
